# Multi-agent continuity study — preliminary engineering report

Three customer-owned model-backed roles worked from the same isolated baseline: integration, implementation and independent validation. Four fresh runs used ABBA ordering (no imported notes / imported historical notes / imported notes / no imported notes). In-run learning was enabled in both conditions. Historical documents remained available to both. The treatment was additional provisional Bot memory, not access to the only copy of the history.

| Run | Imported prior notes | Observed seconds | Model requests | Corrected completion |
|---|---|---:|---:|
| 1 | No | 971.931 | 76 | No |
| 2 | Yes | 452.046 | 40 | No |
| 3 | Yes | 1232.436 | 88 | Yes |
| 4 | No | 979.203 | 68 | No |

One run completed delegated edits, peer retrieval, integration, an actual finite software verification, evidence publication and reflection. Three runs stopped because a proposed lesson referenced an evidence file that did not yet exist; the study runner treated a held reflection as a global stop. Product reflection isolation and this stricter study stop policy are different.

The original final scorer rejected all runs. A supplemental, uniformly applied correction accepted valid ancestor-state evidence when declared inputs and execution provenance remained unchanged. It accepted one run; candidates, model inputs and original results were preserved. This is a post-study measurement correction, not an unqualified original pass.

**No development speedup has been established.** There was no successful baseline run to compare against. Failure-to-stop durations must not be interpreted as time to a successful solution. Two repetitions per condition are insufficient to isolate stochastic model behavior, caching, scheduling and different coordination paths.

Model request intervals covered more than 99% of observed wall time, including provider/network waiting and code/argument generation. This does not measure pure reasoning. The successful run’s verifier process took 0.229 seconds; this study does not establish that CAD geometry computation is the bottleneck.

The captured records show memory applicability decisions, rejected stale lessons, action-linked learning reports, repeated context reads and coordination calls. Those records establish that the path was exercised, not that memory caused better decisions. Rework and unobserved human effort were not assigned fabricated durations.

Next work should address how lessons name unavailable future evidence, isolate reflection failures from unrelated development, and measure repeated context retrieval and coordination on successful matched runs. The bounded software study does not establish physical validity, hardware safety or complete autonomous robot development.

This draft intentionally omits private project identities, design files, source excerpts, participant details and ledger identifiers. Publication still requires the repository’s normal review.

## Separate post-study recovery

A copied failed run was continued after two explicit parent recovery triggers: retry the invalid reflection and resume the interrupted integration task. The model repaired the invalid memory reference, then the team integrated saved contributions and completed finite software verification and reflection. The continuation took 323.544 seconds and 22 model requests; the reflection-repair request took 30.112 seconds, including provider/network waiting. The verifier ran once for 0.115 seconds and passed. The same supplemental provenance-scoring correction accepted the completed evidence. No parent engineering edits were made, and the original trial was unchanged. This demonstrates recoverability with intervention, not uninterrupted autonomy or a matched speedup; it is excluded from the four-run comparison.
